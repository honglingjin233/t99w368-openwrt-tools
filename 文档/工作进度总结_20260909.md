# T99W368 工作进度总结（2026-09-09 会话）

## 一、已完成主线
1. **方案 C 落地**：官方 ModemManager 栈 + 自写 LuCI 插件 modem5g（OpenFi6C 管理 5G 模块）
2. **插件功能全覆盖**（已集成 + 验证）：
   - 状态三卡：连接状态（5G 载波/LTE 锚点信号 RSRP/SINR）/ 模块信息（IMEI/ICCID/IMSI/温度）/ 数据面（IP/会话流量）
   - 控制操作：重拨/制式切换/频段锁定/电源/复位/网络扫描/APN/Ping 诊断/USSD/看门狗状态/AT 查询（13 预设白名单）
   - 短信：收信模式（4G 收发 + 120s 自动回 5G + 后端兜底）/ 发送（自动切 4G 流程）/ 收件箱（**默认折叠防泄露 + 懒加载**）
   - 页面全中文、三卡并排布局、自动刷新开关
3. **AT 逆向突破**：
   - 指令集到手（Quectel RM5xxQ 手册，同 SDX 平台）
   - **ADB 通道打通**：adb（OpenWrt 21.02 ipk）→ 模块内部 root → /dev/at_mdm0 AT 引擎
   - **连续发送模式方法论**：AT 引擎对频繁开关节点不稳定，必须 cat 保持打开 + 连续发命令
   - **实测指令全集**：标准 3GPP（ATI/CGMR/CGSN/CIMI/COPS?/C5GREG?(5G注册)/CFUN?/CGDCONT?/CGACT?/CGPADDR/CGCONTRDP=5(真实IP+DNS)/CSQ/CPIN?/temp?(温度)）+ Foxconn 私有（BOOT_VER?/PLATFORM?/CUSTOMER?/PCIEMODE?/FXLOGLVL?/MODESWITCH?查询）
   - **红线确认**：+MODESWITCH=/+DIAG_ENABLE/+EDL/+EFS_ERASE/+RESET 等绝不执行；AT+USBSWITCH 永不使用（曾软锁死送修）
4. **模块内部全景**（ADB root 遍历）：进程（mbimd/netmgrd/qmuxbridge/atfwd_daemon/fx_set_band/fxgps/fxwakebysms）、QCMAP Web 界面（模块可作独立 CPE）、QMI Perl 调试脚本、/etc/data 配置（L2TP/SOCKS5/LwM2M）

## 二、关键结论
| 问题 | 结论 |
|------|------|
| 5G 短信收发 | **4G 模式全通**；5G NSA 下不可用（工程版固件无 MBN/IMS，sms 通知 no）|
| CA 聚合明细 | **三路径（MM/MBIM/AT）确认不可获取**——工程板固件不暴露（AT+QCAINFO ERROR、AT+debug? 不支持）|
| 命令格式 | T99W368=Foxconn 固件（AT+ 前缀），**无 Quectel Q 系列**（三次实测 ERROR）；T99W175 用 AT^ 前缀（Intel 平台）|
| USSD | 模块不支持（Operation not supported）|
| option ttyUSB | 模块对 USB 接口变更自我保护（ttyUSB 3 分钟漂移）→ 不可用；**ADB 通道是唯一稳定 AT 路径**（不动 USB 枚举）|
| 拨号栈 | MM 栈最优（quectel-CM 实测过，不替换）|
